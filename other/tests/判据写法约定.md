# 验收判据写法约定（2026-11-17 审计后新增）

本目录 320 个脚本负责守生产线的命。它们的**判据本身**也是代码，写歪了会得到两种最坏结果：

1. **假红**：业务改一句提示文案，守卫就红，人开始习惯性「这条老红」——直到真回归混进这批噪声里；
2. **假绿**：判据只匹配源码里出现过的中文串（甚至匹配日志里的一句话），而真正的行为早就变了。

2026-11-17 全仓审计（`审计报告_2026-11-17.md` 🔴17）实测存量：
**62 条判据读 stdout/日志文案、104 条判据拿源码中文文案做 `in`/`==` 比对**（46 个脚本）。

## 硬约定

- **禁止**：断言「源码里存在某段中文提示」「日志里出现某句话」「函数源码里有某个表达式」。
  文案与实现细节都不是契约；改一个字就假红，真回归它抓不到。
- **必须**：断**行为**或断**数据**——真跑一次函数/接口/页面 JS，看返回值、看落盘、看数据库行、
  看 HTTP 状态码、看渲染出来的 DOM/像素。
- 做不到真跑时（需要打印机/真机/外部服务），**显式**打 `[HN-SKIP] <原因>` 并 `exit 0`，
  由 `run_all.py` 记 SKIP 并在汇总行单独报数——**不许**静默 `return 0` 冒充 PASS。
- 变异自证是判据的一部分：写完先把它改坏一次，看着它红，再还原。
- 引用源码只能当**快速定位**（例如找常量表、找 URL），结论必须落在运行时可见的事实上。

## 允许的例外（不改）

- 结构性事实：文件存在、函数定义存在、路由注册表里有这条路（用来抓「整段逻辑被删掉」）。
- 版本号/端口/路径这类**机器契约**常量，且两端都有守卫同时钉住。

## 棘轮

`other/tests/verify_guard_quality.py` 扫描全目录，统计上面两类判据的条数并与基线比对：

- 数量**不许增加**（新增一条就红）——把「写歪」的成本抬起来；
- 减少不报红，只把新数字打出来，等下次改基线；
- 同时检查：三种 `return 0` 伪跳过、缺 node/缺 bash 的静默通过。

按需逐条换成行为判据，换一条就把基线减一条。别一夜之间全删：其中一部分确实在守结构性事实。
