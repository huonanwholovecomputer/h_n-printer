## 3. 判据速查（贴到墙上那种）

**"这次到底提交了几个作业、各几页、什么顺序"** —— 只有一条通道可信：

```powershell
$s = Get-Date "2026-10-15 21:45:00"
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-PrintService/Operational'; StartTime=$s} -ErrorAction SilentlyContinue |
  Where-Object { $_.Id -in 800,801,842,805 } | Sort-Object TimeCreated |
  ForEach-Object { $x=[xml]$_.ToXml(); $leaf=@{}; $x.SelectNodes('//*[not(*)]') |
    ForEach-Object { if ($_.LocalName -notin 'TimeCreated','EventID') { $leaf[$_.LocalName]=$_.InnerText } };
    "{0} | {1} | {2}" -f $_.TimeCreated.ToString("HH:mm:ss"), $_.Id,
      (($leaf.GetEnumerator() | ForEach-Object { "$($_.Key)=$($_.Value)" }) -join ' ') }
```

要点：

- **`800`** = 后台打印作业（入队）、**`801`** = 打印作业、**`842`** = 交打印处理器（**`ErrorCode` 是 `0x0` 才算成功**）、**`805`** = 呈现作业
- 作业是**串行**的：`801` 出现在上一个作业 `842` 之后
- **`PrintService/Admin` 里的 `372` + `1803`「打印机命令无效」是 HP LaserJet 1020 的常态误报** —— 每一次作业都报，包括你亲眼确认打成功的那次。**不能当失败证据**；那条日志里唯一可信的是「文档页面总数」
- **应用日志只说"提交成功"**：`hdc.EndDoc()` 返回后 `print_pdf` 就回 `True`（主机型打印机的 spooler 作业在数据写进端口后就消失，而纸还在出）。所以**判"纸有没有出来"必须看物理结果，不能看日志**

### 4.5 「守卫自身的竞态」这次踩到的（2026-10-15 修）

`verify_cloud_http_fallback.py` 有一条断言原本写成"置 `_connected=True` 后**一次都不能**再拉单"：

```python
client._connected = True
time.sleep(0.3)
check("socket 正常时不再发 HTTP 请求", len(calls) == n_offline)   # ← 随机红
```

**为什么随机**：`CloudClient._pull_fallback_loop` 是「先判 `_connected`、再拉单」。  
置位那一刻若正好落在 `wait(0.05)` 或 `pull_pending(sleep 0.02)` 里，本轮会照旧发出一次 ——  
这是**正常收尾**。机器跑全量套件被占满时该窗口被放大，于是计数偶尔多 1（实测 `5 → 6`；  
单独跑就 `6 → 6`）。

**结论**：**这不是产品缺陷**（真实 `PULL_FALLBACK_INTERVAL` 是 45s，一次在途拉单无害，  
服务端幂等）。**判据要写成"置位后不再有新的调用"**（两次 `sleep` 窗口比对），  
再补一条"至多只多出 1 次"的上界。

**变异自证**（不做这步就可能是"永远为绿"的假守卫）：把源码里 `if self._connected or …`  
改成 `if False and self._connected or …`（= 忽略连接状态、持续轮询），两条判据必须都红：

```
[FAIL] socket 正常时不再发 HTTP 请求  -- 置位后 9 → 13（断开期共 6 次）
[FAIL] socket 正常后至多只多出 1 次在途拉单  -- 6 → 13
```

> **通用教训**：凡"起一个线程 → 改个状态 → 睡一会儿 → 数它调了几次"的守卫，都要问一句  
> "置位那一刻，循环是不是正好在 sleep 里？"——是的话，计数式断言就会随机器负载漂移。
